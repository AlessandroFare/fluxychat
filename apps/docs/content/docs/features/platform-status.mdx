# Platform roadmap status

FluxyChat ships a large surface area. This page documents items that are **not** fully productized yet — so you can plan integrations without surprise.

---

## Research only — do not build on yet

### Agent commerce — x402 (#18) and AP2/UCP (#25)

**Status:** ⚠️ Monitor spec maturity.

- **x402:** HTTP micropayments per tool call (Coinbase facilitator pattern).
- **AP2/UCP:** Google agent payment mandates for agentic commerce.

FluxyChat has **no production x402 or AP2 handler**. Track [FEATURE_ROADMAP](https://github.com/AlessandroFare/fluxychat/blob/main/docs/FEATURE_ROADMAP.md) for spikes.

**Action for you:** None — wait for explicit release notes.

---

## Monitor only — WebTransport (#28)

**Status:** ⚠️ Not for production 2026.

WebSocket remains the default transport. Safari/Firefox WebTransport maturity and server deployment are insufficient for chat production.

**Action for you:** Use WebSocket / SDK reconnect — ignore WebTransport mentions in research docs.

---

## Paid vendor — RCS channel (#17)

**Status:** ⬜ Adapter scaffold; **requires Twilio or MessageBird RCS account**.

WhatsApp + web native channels work today. RCS outbound needs vendor credentials.

**Action for you:**

1. Open a Twilio/MessageBird RCS program (paid).
2. Set `RCS_OUTBOUND_URL` on Worker when approved.
3. Use [Channel forms](/docs/features/channel-forms) for structured RCS replies.

Until then: use WhatsApp forms or in-app chat.

---

## VPS / GPU — voice clone translation (#27)

**Status:** ⬜ Not on Cloudflare Workers.

Unified [voice pipeline](/docs/guides/voice-ai-pipeline) runs on Workers AI. **Voice cloning + translation in target language** needs OmniVoice/RVC-style pipeline on a GPU or strong CPU VPS.

**Action for you:**

1. Use standard voice AI on Workers today.
2. For clone-quality translation, plan a separate media server (2027 roadmap).

---

## Partial — omnichannel adapters (Slack, Teams, Discord, …)

**Status:** 🟨 Webhook stubs exist; **production needs per-vendor OAuth + signature verification**.

15 adapters are listed in code (`cross-platform.js`). Each vendor requires:

- Developer app registration
- OAuth or bot token storage in `channel_configs`
- Webhook URL + signing secret

**Action for you:** Pick one channel → follow vendor docs → configure in console **Bridges**. Do not assume all 15 are turnkey.

Native **web** channel is fully supported.

---

## Partial — IoT fleet & spatial (#29 adjacent)

**Status:** 🟨 Location tracking + FluxyTrack SDK exist; **predictive fleet layer not shipped**.

- **Today:** [Platform IoT](/docs/platform/iot), geofencing in SDK, location privacy TTL.
- **Not yet:** Predictive maintenance, digital twin spatial audio product layer.

**Action for you:** Use location SDK for fleet visibility; treat predictive features as roadmap.
