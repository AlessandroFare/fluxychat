# Voice stages

Split voice participants into speakers and listeners. Only speakers publish audio by default. Listeners request to speak or are promoted by moderators.

## Console / in-room UI

**Voice AI** (`/voice-ai`) and the in-room Voice stage panel (`VoiceStagePanel`):

- Toggle speaker / listener role
- Request to speak queue for listeners
- Moderator promote / demote
- Active speaker highlight (Silero VAD)

## Active speaker

`useVoiceStageVad` plus Silero VAD highlights who is speaking. Same pipeline as [voice AI](/docs/guides/voice-ai-pipeline).

## API

```http
GET  /rooms/:roomId/voice-stage
POST /rooms/:roomId/voice-stage/join
POST /rooms/:roomId/voice-stage/leave
POST /rooms/:roomId/voice-stage/role
POST /rooms/:roomId/voice-stage/mute
POST /rooms/:roomId/voice-stage/request-speak
POST /rooms/:roomId/voice/token
```

WS: `stage_join` / `leave` / `mute` / `request_speak` / `promote`. After reconnect the SDK re-sends the last `stage_join` (LiveKit Room reconnect HOW, signaling only).

Media is not this API. Mint `getVoiceToken` (or `createVoiceTokenSource` to cache until expiry) then connect `livekit-client` yourself. `canPublish: false` / `canSubscribe: false` map to LiveKit JWT grants. Identity is the member JWT, not a spoofed `userId`.

## Environment

Voice pipeline env vars (`AI_*`, TURN) apply when WebRTC is used alongside stages.

Ideal for AMAs, town halls, and large voice rooms without everyone unmuted.
