# Channel structured forms

Define a **form schema** once; deliver it on WhatsApp (interactive messages / Flows) or RCS (suggested replies). Answers arrive as a structured message in the FluxyChat room.

## Console

**Bridges → Forms** (`/bridges/forms`)

1. Pick a **room** and recipient **E.164** number.
2. Choose channel: **WhatsApp** or **RCS**.
3. **Send structured form** — worker creates a delivery record and calls the channel adapter.
4. Copy **inbound webhook URLs** for Meta / RCS aggregator configuration.
5. Review **Recent deliveries** (status, responses, timestamps).

## Field types

| Type | Use |
|------|-----|
| `select` | Single choice from options |
| `yes_no` | Boolean step |
| `rating` | Numeric scale |
| `text` | Free text |

## API

```http
POST /channel-forms/dispatch
GET  /channel-forms/deliveries?roomId=&limit=
POST /webhooks/channel-forms/whatsapp
POST /webhooks/channel-forms/rcs
```

Dispatch body: `{ roomId, channel, recipientE164, schema?, formId?, channelConfigId? }`.

## WhatsApp

Requires Meta Business API credentials. See [Optional integrations — WhatsApp](/docs/guides/ecosystem/optional-integrations#whatsapp-business-structured-forms).

Set `WHATSAPP_*` env vars on the Worker (token, phone number ID, verify token).

## RCS

Requires a paid RCS aggregator — see [Platform status — RCS](/docs/features/platform-status#rcs-17).

## Dry-run

Without vendor credentials, submissions are stored locally for UI testing — useful for schema iteration before going live.
