## Market Landscape 2026 — Dove siamo e dove vogliamo arrivare

### Convergenza del mercato: Chat × Realtime × AI Agents = battleground 2026

Il mercato nel 2026 si è biforcato in due tier, e **la convergenza è la zona vincente**:

| Tier | Esempi | Punti forti | Punti deboli |
|------|--------|-------------|--------------|
| **Chat API Providers** | Stream, Sendbird, Ably Chat, Pusher | Chat primitives mature, UI kit, compliance | AI è un add-on separato, pricing opaco per volumi medi, nessun self-host MIT |
| **AI Agent Infra** | LiveKit, Daily, Liveblocks AI Copilots, Vercel AI SDK 7 | Voice/video AI nativo, agent framework moderni | Nessuna chat persistente/history, no operator console per customer-facing chat |
| **AI-Native Chat Platform (NOI)** | **FluxyChat** | **Entrambi i mondi su un singolo Worker kernel: chat persistente + AI agents + voice + self-host MIT + 14 canali omnichannel + moduli verticali** | Ad oggi: SDK surface da pulire (stub), alcuni UX polish, package split, DevTools, status page — tutto trackabile in questa roadmap |
| **Chat-first Lightweight SDK** | Portal | DX molto curata, package split, piccolo bundle | Nessuna AI, nessun self-host, nessuna enterprise feature, solo chat |

### Trend 2026 che dobbiamo cavalcare per diventare punto di riferimento

Fonte: ricerche interne, Vercel AI SDK 7 (16M+ weekly downloads), OpenAI Responses API con MCP nativo, report QuickBlox/TRTC 2026, analisi gap `FLUXYCHAT-GAPS-2026.md`.

| # | Trend | Perché conta | Dove lo posizioniamo |
|---|-------|-------------|----------------------|
| 1 | **AI SDK 7 come standard de facto per agenti** | reasoning param standard, tool/runtime context, WorkflowAgent, MCP Apps, telemetry OTel, lifecycle callbacks | **Integrare pattern Vercel AI SDK 7** nel nostro agent layer — così i dev conoscono già le API quando arrivano su FluxyChat |
| 2 | **MCP (Model Context Protocol) = standard industriale** | OpenAI l'ha messo nativamente in Responses API + Steering Committee; tutti i provider lo adottano | **MCP client + server già presenti** — elevare a first-class citizen, docs, marketplace di server MCP pre-connessi |
| 3 | **Realtime Voice (speech-to-speech) < 300ms** | OpenAI Realtime API = standard; Gemini Live come adapter; LiveKit/Daily già scalano | **Voice pipeline end-to-end cross-provider** con adapter OpenAI Realtime + fallback Gemini Live (stesso pattern di successo nel mercato) |
| 4 | **Durable AI Sessions (sopravvivono a disconnect/reload)** | Ably AI Transport, WorkflowAgent di Vercel — gli utenti si aspettano che l'agente continui da dove era | **AI Transport layer** con resumable token streaming, multi-device state sync |
| 5 | **Developer Experience = differenziatore principale** | I dev scelgono il SDK che li fa spedire in produzione in 5 min con meno bug | Package split (protocol/core/react), error hierarchy tipizzata, testing utilities, DevTools inspector, status page pubblica |
| 6 | **Compliance + Enterprise = moat crescente** | DSA EU, EU AI Act, HIPAA, SOC 2 Type 2, DLP PHI/PCI | Consolidare SSO/SAML, DLP, audit, retention già esistenti — aggiungere governance AI, CMK, e-discovery |
| 7 | **Offline + reconnect = dove i bravi SDK si distinguono** | Le demo funzionano tutte; la qualità si vede in weak network, background, handoff 4G→WiFi | Outbox persistente, delivery receipts, message ordering guarantees, reconnect senza perdite |
| 8 | **Knowledge base + RAG integrato** | Nessuno vuole connettere manualmente Notion/Confluence/GDrive | Connectors pre-built per KB → RAG automatico per agenti |
| 9 | **Pricing chiaro + self-host MIT** | Startup e indie dev odiano le sorprese a fine mese; vogliono lock-in zero | **Il nostro positioning principale!** $1/1M messaggi, MIT self-host, nessun vendor lock-in |

### Cosa cercano i dev oggi (pain points da risolvere)

Fonte: ricerche QuickBlox/TRTC e analisi HN/Dev.to commenti

1. **"Pusher/Ably costano troppo anche per volumi modesti"** → il nostro pricing lo batte
2. **"La demo funziona, ma in weak network il SDK perde messaggi"** → reconnect + outbox + delivery receipts (Fase 1)
3. **"L'AI è un add-on separato che non si integra con la chat history"** → AI agents nativi nella room (nostro punto forte!)
4. **"Errori SDK non documentati, debug impossibile"** → error hierarchy tipizzata + DevTools (Fase 1/2)
5. **"Per voice devo integrare LiveKit a parte"** → voice pipeline end-to-end (Fase 3)
6. **"Per SSO/SCIM devo pagare enterprise plan"** → già incluso nel nostro stack!
