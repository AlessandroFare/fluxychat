# One-Click Full Product — Roadmap DX

**Status:** 🔴 P0 product promise gap (identified 2026-08-19)  
**Owner:** `@alefare`  
**Related:** [BEAT-PORTAL-ROADMAP.md](/docs/BEAT-PORTAL-ROADMAP) (Fase 1 DX), [create-fluxy-chat guide](/docs/docs/guides/create-fluxy-chat), `scripts/first-message.mjs`, `packages/create-fluxy-chat/`

---

## Problema

Un visitatore GitHub (dev o non-dev) legge il README, esegue **un comando** dal terminale e si aspetta di avere **tutto FluxyChat** in pochissimo tempo:

- chat realtime funzionante in browser
- agente AI (`@assistant`) con risposta e tool visibili
- console operatore (rooms, agents, JWT)
- percorso chiaro verso self-host **o** hosted

**Oggi non è vero.** Ogni entry point copre solo un pezzo del prodotto.

---

## Stato attuale — cosa dà ogni percorso

| Entry point | Cosa ottieni subito | Cosa manca |
|-------------|---------------------|------------|
| `git clone` + `pnpm run first-message` | Worker locale, project + JWT, first message in terminale | Browser UI, agent, console, due tab demo |
| `npx create-fluxy-chat --template react` | App Vite + `useChat` / widget | Worker, credenziali `.env`, agent invoke, console |
| `npx create-fluxy-chat --minimal` | Widget ui-kit | Idem |
| `npx create-fluxy-chat --adapter basic/web/...` | Worker bot (webhook) | Nessuna chat UI |
| `pnpm add @fluxy-chat/sdk` | Libreria | Tutto il resto (setup manuale) |
| [fluxychat.com](https://fluxychat.com) signup / `/demo` | Prodotto completo hosted | Non parte da un comando terminale |
| `pnpm dev` (monorepo) | Dashboard + worker + docs | Richiede clone, install, `.dev.vars`, minuti di setup |

### Gap narrativo (marketing vs realtà)

- **README root:** punta a `git clone` + `first-message` → percorso **contributor/monorepo**, non “npm install e via”.
- **Marketing / npm:** punta a `create-fluxy-chat` / `pnpm add @fluxy-chat/sdk` → **chat-only client**, non piattaforma.
- **Video demo:** per mostrare tutto serve oggi un **salto** da progetto scaffold a produzione hosted.

---

## Esperienza target (North Star)

> **Un comando → ≤90 secondi → prodotto completo usabile in browser**, con prove visibili di realtime, AI e console.

### Personas

| Persona | Obiettivo | Path preferito |
|---------|-----------|----------------|
| **Dev GitHub** | Integrare chat + agent in app propria | CLI → app locale + console |
| **Dev curioso** | Capire se FluxyChat fa per il suo stack | CLI → sandbox hosted (zero wrangler) |
| **Founder / PM** | Vedere demo credibile senza DevOps | CLI → browser full product (hosted sandbox) |

### Definition of Done (E2E macchina pulita)

1. Comando unico documentato nel README (non tre percorsi diversi).
2. Browser si apre (o URL stampato) su chat **con messaggio inviato**.
3. `@assistant` risponde (LLM configurato o sandbox hosted).
4. Console raggiungibile (locale `:3000` o link hosted) con project/room visibili.
5. Due tab/browser → stesso room, messaggio istantaneo.
6. Tempo totale **≤90s** (install escluso se `--skip-install` + pre-bundled, max 120s con install).
7. CI smoke: `pnpm test:one-click` verde su Ubuntu + Windows.

## Architettura proposta — due modalità, un CLI

```
npx create-fluxy-chat my-app
        │
        ├─► [--mode hosted]     default per "voglio tutto subito"
        │       • device code / browser OAuth → project sandbox su fluxychat.com
        │       • scrive .env (worker URL, JWT, roomId)
        │       • avvia Vite + apre /console link
        │
        └─► [--mode local]      default per self-hosters
                • wrangler dev (worker) in background
                • auto-provision (estende first-message)
                • seed @assistant + LLM da .dev.vars o Ollama hint
                • Vite app + optional dashboard lite o link :3000
```

**Regola README:** un solo comando hero; flag `--mode` per power user.
