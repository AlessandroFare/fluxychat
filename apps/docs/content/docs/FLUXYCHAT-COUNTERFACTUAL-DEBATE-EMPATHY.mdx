# 1. Counterfactual Replay (`#44`)

## 1.1 Pitch

Rigirare un punto della conversazione con scelta diversa (tool/params) e
mostrare esiti fianco a fianco — senza toccare la cronologia originale.

## 1.2 Gap

- `message-branch.js` ✅ + `agent_runs` / OTel ✅ — nessun competitor
  unisce entrambi in UX "prova alternativa".

## 1.3 Architettura

```
Timeline → [tool_call] → utente "Prova alternativa"
  → message-branch.js (nuovo branch_id)
  → WorkflowAgent riesegue con params modificati
  → UI due colonne (originale | alternativo)
  → opzionale: promuovi branch a main
```

## 1.4 Data model

```sql
ALTER TABLE agent_runs ADD COLUMN branch_id TEXT;
ALTER TABLE agent_runs ADD COLUMN counterfactual_of TEXT;
ALTER TABLE agent_runs ADD COLUMN modified_params TEXT;
```

## 1.5 Guardrail

- Max 1 livello di counterfactual annidato.
- Avviso costo per tool a pagamento.
- `dry_run: true` per side-effect (email, pagamenti) — mai riesecuzione reale.

## 1.6 Touchpoint

| Componente | Riuso |
|---|---|
| Hover menu | `fluxychat.tsx` |
| Branch | `message-branch.js`, `POST /rooms/:roomId/branch` |
| Editor params | `generative-ui.ts` |
| Esecuzione | `WorkflowAgent` + `branch_id` |
| Telemetria | `agent_runs`, `otel-export.js` |

## 1.7 Fasi

| Fase | Contenuto | Effort |
|---|---|---|
| MVP | Branch singolo tool_call, UI 2 colonne | 1–2 sett |
| V1 | Dry-run side-effect, limite profondità | 1 sett |
| V2 | Promozione branch con merge UI | 1 sett |

**Priorità:** 🟡 Next · **Effort totale:** ~4 sett

# 2. Multi-Agent Debate UX (`#45`)

## 2.1 Pitch

Mostrare in diretta nella room il debate tra 2–3 agenti "esperti" prima
della risposta finale — non nascosto come LangGraph/CrewAI.

## 2.2 Architettura

```
Utente → Orchestrator (moderatore WorkflowAgent)
  → Agente A, B, C postano agent_step visibili
  → Dopo N round → sintesi finale unica
```

## 2.3 Evento timeline

```ts
{
  type: "agent_step",
  agent_id: "agent-tech-perspective",
  participant_role: "debate",
  round: 1,
  content: "Dal punto di vista tecnico..."
}
```

## 2.4 Data model

```sql
CREATE TABLE debate_roles (
  id TEXT PRIMARY KEY,
  tenant_id TEXT,
  trigger_pattern TEXT,
  role_name TEXT,
  system_prompt TEXT,
  max_rounds INTEGER DEFAULT 2
);
```

## 2.5 Guardrail

- Max round configurabile (default 2).
- Timeout → "consenso parziale".
- Telemetria costo token/latenza vs risposta singola.

## 2.6 Touchpoint

| Componente | Riuso |
|---|---|
| Orchestrazione | `WorkflowAgent` |
| Eventi | bus `tool_call` / `agent_step` |
| UI thread debate | `generative-ui.ts` |
| Costo | `/agents/observability` |

## 2.7 Fasi

| Fase | Contenuto | Effort |
|---|---|---|
| MVP | 2 ruoli fissi, 1 round | 2 sett |
| V1 | Ruoli configurabili tenant | 1 sett |
| V2 | Dashboard costo debate | 1 sett |

**Priorità:** 🟡 Next · **Effort totale:** ~4 sett

# 3. Empathy Layer — voice rooms (`#46`)

## 3.1 Pitch

Rilevare frustrazione/stress nel tono (prosodia), adattare silenziosamente
comportamento agente — non solo *quando* parlare (VAD #10).

## 3.2 Architettura

```
Audio → Silero VAD (#10)
  → Prosody extractor (pitch, speech rate, pause ratio) — DSP client-side
  → Classificatore regole: calm | frustrated | stressed | neutral
  → Agent Behavior Modulator (prompt dinamico, escalation umana)
```

## 3.3 Data model

```ts
interface ProsodySignal {
  room_id: string;
  user_id: string;
  turn_id: string;
  pitch_variance: number;
  speech_rate: number;
  pause_ratio: number;
  inferred_state: "calm" | "frustrated" | "stressed" | "neutral";
  confidence: number;
}
```

Nessuna persistenza prosodia grezza di default — opt-in tenant.

## 3.4 Guardrail (critici)

- **Mai** dire "sembri stressato" all'utente — solo adattamento silenzioso.
- Bassa confidenza → nessuna azione.
- Opt-in esplicito; no profilazione persistente.
- Escalation umana sempre disponibile e più visibile se stress alto.

## 3.5 Touchpoint

| Componente | Riuso |
|---|---|
| VAD | `voice-turn-detection.ts`, `voice-ai-pipeline.js` |
| Prosody | nuovo modulo client DSP |
| Modulazione | `WorkflowAgent` |
| Consenso | data residency / consent (#42) |

## 3.6 Fasi

| Fase | Contenuto | Effort |
|---|---|---|
| MVP | Feature base + 2 stati | 2 sett |
| V1 | Modulazione agente + opt-in UI | 2 sett |
| V2 | Emotion model opzionale self-hosted | esplorativo |

**Priorità:** 🟢 Later · **Rischio:** privacy/percezione invasiva
