You are wiring a product on FluxyChat. Use **this page** plus [llms.txt](/llms.txt). Do not invent a second realtime vendor.

## Gold path

```bash
npx @fluxy-chat/create-fluxy-chat@latest my-app --mode hosted -y
```

Live cursors (two browser tabs):


## Three ways to run

| Path | Command | You provide |
| --- | --- | --- |
| Hosted | `--mode hosted -y` | Clerk on fluxychat.com after setup |
| Self-host | clone repo, `pnpm --filter @fluxy-chat/worker dev` | Worker URL + project JWT |
| SDK-only | `--template react` or `--example` from the [gallery](/docs/getting-started/gallery) | Worker URL + JWT or public room |

Always use `@fluxy-chat/create-fluxy-chat`. Bare `npx create-fluxy-chat` 404s.

## Env vars (browser)

- `VITE_FLUXYCHAT_WORKER_URL` — hosted API or `wrangler dev`
- `VITE_FLUXYCHAT_MEMBER_JWT` + `VITE_FLUXYCHAT_ROOM_ID` — member
- `VITE_FLUXYCHAT_PUBLIC_ROOM_ID` — guest via `FluxyChatClient.joinPublicRoomAsGuest`

Project API keys (`fc_…`) stay on the **server**.

## One WebSocket per room

`useChat({ roomId })` is the room session: messages, presence, cursors (`sendCursor` / `liveCursors`), broadcast (`sendClientEvent`), agents (`invokeAgent`).

For cursors-only, `useLiveCursors({ roomId })`. Do **not** mount both without the same `sessionScope` — that opens two sockets.

## Liveblocks-shaped map (what exists vs roadmap)

| Liveblocks | FluxyChat now | Do not |
| --- | --- | --- |
| Presence (users, cursors, selections) | `presenceMembers`, `liveCursors`, `sendCursor`, `useMyPresence` / `presence_patch` | `client_event` for pointers |
| Broadcast | `sendClientEvent` / `useBroadcastEvent` (`client-ephemeral-*` skips webhooks) | 60 Hz through broadcast |
| Storage | `useStorage` / `useMutation` / `FluxyYjsProvider` (`@fluxy-chat/sdk/yjs`); LiveFile via `uploadLiveFile`; Tiptap `--example tiptap-room` | A new CRDT product |
| Feeds | `useFeeds`, `/rooms/:id/feeds` (JWT or API key) | Mixing with chat `messages` |
| Copilot | `RegisterAiKnowledge` + `useAiChat` + `<AiChat />` (keyless mock) | Treating it as `invokeAgent` |
| Threads / Comments | `useThreads`, `/rooms/:id/comment-threads` | Mixing with chat `parentId` replies |
| Chat | `useChat` messages | MQTT |
| Agent as peer | `invokeAgent` on the timeline | A separate agent socket |

Storage helpers (`useStorage`) ship on `@fluxy-chat/sdk/yjs`. Feeds and Copilot `<AiChat />` are shipped (feeds ≠ chat; copilot ≠ `invokeAgent`). Do not promise HIPAA/netcode/FDA.

## JWT mint (server)

Your backend POSTs `POST {WORKER}/auth/token` with `X-Fluxy-Api-Key: fc_…` and body `{ userId, roles, ttlSeconds }`. Pass the JWT as `FluxyRealtimeProvider` **`authTokenProvider`** (not `token`). `FluxyYjsProvider` uses **`token`**. See [Choose your path](/docs/getting-started/choose-your-path) and the auth cookbook.

## Open two tabs

Collab features are untestable in one tab. Live cursors, presence, and chat all need a second client on the same `roomId`.
