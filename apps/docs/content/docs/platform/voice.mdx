Dashboard: [**Voice AI**](/voice-ai).

The Worker runs **speech in-process** when the `[ai]` binding is present (`env.AI.run`):

| Direction | Model | HTTP |
|-----------|--------|------|
| STT | `@cf/openai/whisper-large-v3-turbo` | `POST /voice-ai/transcribe` and async `POST /messages/voice` |
| TTS | `@cf/myshell-ai/melotts`, fallback `@cf/deepgram/aura-1` | `POST /voice-ai/speak` |

Voice-message uploads still land on R2 and the room WebSocket (`kind: "voice"`). Transcription prefers Workers AI, then OpenAI-compatible `AI_BASE_URL` if you BYOK.

Realtime duplex (OpenAI Realtime / Gemini Live) stays on the client SDK (`createVoicePipeline` / `useVoice`) for sub-300ms barge-in. Session metrics remain on `/admin/voice-ai/*`.

## In-worker transcribe / speak

```bash
curl -X POST "$WORKER_URL/voice-ai/transcribe" \
  -H "Authorization: Bearer $JWT" \
  -H "Content-Type: application/json" \
  -d '{"audioBase64":"<base64>","mimeType":"audio/webm","roomId":"support"}'

curl -X POST "$WORKER_URL/voice-ai/speak" \
  -H "Authorization: Bearer $JWT" \
  -H "Content-Type: application/json" \
  -d '{"text":"Room is live","lang":"en"}'
```

Set `announce: true` with a `roomId` you can access to fan out `voice_ai_transcript` / `voice_ai_speak` on the room bus (text only; speak does not broadcast the audio blob).

## Latency SLO

| Tier | Target | Path |
|------|--------|------|
| **Realtime duplex** | P95 ≤ 300ms end-to-end | OpenAI Realtime WebSocket (`openai-realtime`) |
| **Acceptable duplex** | P95 ≤ 350ms | Gemini Live (OpenAI-compatible WS surface) |
| **In-worker REST** | Best effort (~800ms target) | Workers AI Whisper + TTS (`workers-ai`) |
| **BYOK REST** | Best effort | Chunked `AI_BASE_URL` transcriptions |
| **Demo / offline** | N/A | Text-only pipeline (`useVoice` simulation) |

Report duplex samples via `POST /admin/voice-ai/metrics` and inspect aggregates on `/voice-ai`.

## Transport fallback ladder

The SDK degrades automatically when a faster path is unavailable:

```
realtime (OpenAI/Gemini WS)
  ↓ mic denied / WS error / missing API key
chunked (REST STT + TTS — Worker /voice-ai/* or AI_BASE_URL)
  ↓ provider error
text_only (LLM + TTS text path — dashboard demo default)
```

```typescript
import { useVoice } from "@fluxy-chat/react";

const voice = useVoice({
  preferredTransport: "realtime",
  autoFallback: true,
  noiseSuppression: true,
  echoCancellation: true,
  onMetrics: ({ totalLatencyMs }) => {
    if (totalLatencyMs > 300) console.warn("above SLO");
  },
});

await voice.start();
console.log(voice.pipeline?.getActiveTransport()); // realtime | chunked | text_only
```

Listen for `transport_fallback` events on the pipeline when debugging production paths.

## Worker session (metrics)

```bash
curl -X POST "$WORKER_URL/admin/voice-ai/sessions" \
  -H "Authorization: Bearer $ADMIN_JWT" \
  -H "Content-Type: application/json" \
  -d '{"providerId":"workers-ai","roomId":"support"}'
```

Returns `targetLatencyMs` and a session `wsUrl` for client realtime audio. Speech itself is `POST /voice-ai/transcribe` and `POST /voice-ai/speak`.

## Room integration

Voice sessions optionally bind to a `roomId`. Agent replies and voice message transcriptions appear on the **same room WebSocket** as chat (`message` with `kind: "voice"`). See [Voice AI pipeline guide](/docs/guides/voice-ai-pipeline).
